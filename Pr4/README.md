# API книжкового магазину

REST API для керування інвентарем книг, обробки покупок та відстеження замовлень клієнтів. Реалізовано на FastAPI, дані зберігаються в пам'яті застосунку.

## Структура проєкту

- `app/main.py` - API та логіка магазину (клас `Bookstore`)
- `tests/test_bookstore.py` - тести логіки та ендпоінтів (pytest)
- `postman_collection.json` - колекція запитів для Postman
- `requirements.txt` - залежності

## Розгортання та встановлення

Протестовано на Python 3.14.3.

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

На Linux та macOS активація: `source .venv/bin/activate`.

## Запуск локально

```
uvicorn app.main:app --reload
```

Сервер працює за адресою http://127.0.0.1:8000. Інтерактивна документація Swagger доступна на http://127.0.0.1:8000/docs.

## Запуск тестів

```
python -m pytest -v
```

Тести виконуються в корені проєкту. Кожен тест використовує окреме порожнє сховище, тому вони не залежать один від одного.

Покриття тестами:

- інвентар: створення книги, заборона дубліката ISBN, оновлення, заборона зміни ISBN, видалення за ID та ISBN, видалення неіснуючої книги;
- покупки: успішне оформлення, відмова при відсутній книзі або нестачі примірників, зменшення кількості, атомарність замовлення;
- замовлення: унікальні ідентифікатори, склад замовлення, зміна статусу, список замовлень клієнта.

## Опис API

### Книги

| Метод | Ендпоінт | Опис | Успішна відповідь |
|-------|----------|------|-------------------|
| POST | `/books/` | Додати книгу | 201 |
| GET | `/books/` | Список усіх книг | 200 |
| GET | `/books/{book_id}` | Книга за ID | 200 |
| PUT | `/books/{book_id}` | Оновити ціну, кількість або опис | 200 |
| DELETE | `/books/{book_id}` | Видалити книгу за ID | 204 |
| DELETE | `/books/isbn/{isbn}` | Видалити книгу за ISBN | 204 |

Тіло `POST /books/`:

```json
{
  "isbn": "123456789",
  "title": "Python Programming",
  "author": "John Doe",
  "price": 10.5,
  "quantity": 5,
  "description": "Підручник"
}
```

Поля `isbn`, `title`, `author` обов'язкові й не можуть бути порожніми, `price` та `quantity` не можуть бути від'ємними, `description` необов'язкове.

Тіло `PUT /books/{book_id}` (усі поля необов'язкові):

```json
{
  "price": 12.0,
  "quantity": 8,
  "description": "Нове видання"
}
```

Інші поля, зокрема `isbn`, змінювати не можна: такий запит повертає 422.

### Замовлення

| Метод | Ендпоінт | Опис | Успішна відповідь |
|-------|----------|------|-------------------|
| POST | `/orders/` | Створити замовлення | 201 |
| GET | `/orders/{order_id}` | Замовлення за ID | 200 |
| PUT | `/orders/{order_id}` | Змінити статус замовлення | 200 |
| GET | `/customers/{customer_id}/orders` | Замовлення клієнта | 200 |

Тіло `POST /orders/`:

```json
{
  "customer_id": 1,
  "items": [
    {"book_id": 1, "quantity": 2}
  ]
}
```

Замовлення створюється зі статусом `processing`, кількість книг у інвентарі зменшується одразу. Якщо хоча б для однієї позиції не вистачає примірників, замовлення не створюється й наявність не змінюється.

Тіло `PUT /orders/{order_id}`:

```json
{
  "status": "shipped"
}
```

Допустимі статуси:

| Значення | Значення українською |
|----------|----------------------|
| `processing` | на обробці |
| `shipped` | відправлено |
| `completed` | виконано |

### Коди помилок

| Код | Причина |
|-----|---------|
| 404 | книгу або замовлення не знайдено |
| 409 | книга з таким ISBN вже існує або недостатньо примірників |
| 422 | некоректні дані запиту |

Тіло помилки має вигляд `{"detail": "..."}`.

## Тестування в Postman

1. Імпортуйте файл `postman_collection.json` (Import).
2. Змінна колекції `baseUrl` вказує на `http://127.0.0.1:8000`, тому перед запуском колекції сервер має працювати.
3. Запустіть колекцію через Collection Runner: запити виконуються по порядку, ID книги та замовлення передаються між ними автоматично, а перевірки відповідей виконуються у вкладці Tests кожного запиту.
